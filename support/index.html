When reporting an issue

  1. Include the SessionsAhead version and build if known.
  2. Describe what you were doing, such as connecting Calendly, checking a series, resolving a conflict, booking, resuming, or cancelling.
  3. Include the on-screen message, screenshot, or screen recording if useful.
  4. Tell us whether the issue still happens after reopening the app.

To protect privacy, please do not proactively send OAuth credentials, full client lists, booking exports, or other sensitive information. If deeper troubleshooting is needed, we will first explain the minimum information required.

Frequently asked questions

Does SessionsAhead replace Calendly?

No. It uses your existing supported Calendly event types and creates real Calendly bookings.

Why can't I use every Calendly event type?

Version 1.0 supports active, one-on-one, non-paid instant-book event types with no location or a single Zoom location. Team, round-robin, and paid event types are outside this release.

What happens if booking is interrupted?

Use Resume booking. SessionsAhead checks Calendly before retrying so an interrupted request does not blindly create duplicate bookings.

What happens when I disconnect Calendly?

The app removes its stored Calendly credentials. Existing Calendly bookings are not deleted, and saved local series records remain on the device.

Does SessionsAhead have its own account, ads, or subscription?

No SessionsAhead account is required. Version 1.0 does not include third-party ads, behavioral analytics SDKs, subscriptions, or in-app purchases. The app is sold as a one-time paid download.
